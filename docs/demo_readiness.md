# Demo 完成度與戰鬥手感計畫（2026-09-12）

## 結論

單人核心玩法已能完整對局，但公開 Demo 還缺「效果辨識、第一次上手、固定牌組、音量控制、發佈驗收」五個關卡。連線不列入本輪門檻；先把每次操作做成玩家看得懂、聽得懂、能預測結果的完整回饋，再增加更多卡片。

```text
玩家操作 → 先兆（選取／瞄準）→ 動作（卡牌或角色動畫）→ 結果（VFX＋SFX＋數字）→ 狀態落地
```

目前已有 132 張卡、完整單人 AI、13 個通用 SFX、角色攻擊／受傷／死亡動畫、飄字、通用傷害粒子及回魔洞演出。主要問題是多種規則共用同一個 `SPELL_CAST` 與 `FxBurst`，火焰、冰凍、治療、護盾、反制和伏印在畫面上缺少各自的辨識特徵。

## 建議接法

不要為 132 張卡各寫一段特效程式；先依效果家族共用，再讓少數傳說卡覆寫。

```text
BattleManager 結算
        ↓（傷害、治療、狀態、召喚等結果）
CardManager 發出演出事件
        ↓
FxDirector 依 effect／status／modifier 選 FxProfile
        ├─ AnimatedSprite3D：像素幀動畫
        ├─ FxBurst：補火花、泛光與空間感
        └─ Sfx：播放對應音效家族
```

`SkillData.effect`、`status`、`modifier` 已能決定大部分效果；只有需要特殊演出的卡才新增可選 `vfx_id`。例如「火焰爆裂」由 `status=BURN` 自動選火焰施法＋火焰命中，「赤曜古龍」再用 `vfx_id` 覆寫成較大的傳說級版本。

| 效果家族 | 最低演出 | 可重用卡片 |
|---|---|---|
| 斬擊／穿刺／鈍擊 | 攻擊軌跡＋不同命中聲＋短促火花 | 普攻與物理技能 |
| 火／冰／雷／毒／暗影 | 施法先兆＋命中特效＋各自音色 | 元素秘術、狀態技能 |
| 治療／護盾／增益 | 由下往上亮起；不得播放受擊動畫 | 治療、鍛強、鐵壁 |
| 召喚／復活／死亡 | 落地或聚合＋短停頓＋結果音 | 戰吼、亡者召集、不滅 |
| 瞬咒／伏印 | 揭牌／破裂／抵銷三段，讓守方介入可見 | 反制窗口、宿主伏印 |
| 回魔／棄牌／爆牌 | 卡牌吸入黑洞＋魔力飛向 HUD＋入帳聲 | 丟牌回魔、滿手燒牌 |

像素效果以 `nearest` 過濾、固定世界尺寸與固定 FPS 播放；現有 `FxBurst` 保留為第二層火花，不拿它取代主效果。`reduce_motion` 開啟時改播首尾兩幀、停用鏡頭震動與大幅縮放。

## UI／UX 完成度

戰鬥 HUD 已有清楚的回合條、`◆／◇` 魔力、雙方紅盾生命值、卡牌 hover 詳情、瞄準箭頭、離開確認與勝負畫面；它已經有可用骨架，但「現在能做什麼、剛才發生什麼」仍不夠清楚。

| 優先 | UI 項目 | 現況 | Demo 前怎麼補 |
|---|---|---|---|
| P0 | 行動狀態 | 回合條會換字色，但結束回合鍵沒有依我方／對方回合切換 disabled 外觀 | 我方回合亮起；對方／AI 行動／反制等待時鎖定並顯示簡短原因 |
| P0 | 可出牌提示 | 拖曳卡槽有合法目標高亮，魔力不足多半在操作後才跳文字 | 手牌先標出「可用／魔力不足／無合法目標」，不要逼玩家逐張試錯 |
| P0 | 結算紀錄 | `flash_message()` 約一秒後消失，複合技能與反制容易來不及讀 | 增加最近 4–6 筆可收合行動紀錄；短訊仍保留作即時回饋 |
| P0 | 反制與伏印 | 已有瞬咒詢問窗與伏印警戒，但結算主要靠文字 | 面板固定顯示施法卡、反制卡、費用與結果；伏印觸發要有揭示動畫 |
| P0 | 戰鬥資訊辨識 | hover 詳情完整，場上狀態仍偏文字 | 用 Icons 包補狀態與關鍵字圖示，hover／tooltip 再顯示完整規則 |
| P0 | 解析度與 UI 比例 | 已支援 720p–1440p、100／125／150% 與高對比；新戰鬥 HUD 尚需完整重驗 | 至少驗 1280×720、1920×1080、2560×1440，並各驗 100%／150% 不互蓋 |
| P0 | 畫面一致性 | 戰鬥 HUD 已改成低彩度暗色金屬；主選單、設定、圖鑑與各彈窗仍要一起比對 | 統一字級、按鈕狀態、邊距、焦點框與確認／取消位置，不再加整張 AI 背景 UI |
| P1 | 墓地與牌堆資訊 | 墓地只有頂牌與張數，牌堆只顯示張數 | 墓地可開公開清單；牌堆維持隱藏內容，只補 tooltip |
| P1 | 非滑鼠操作 | 選單具鍵盤焦點，3D 卡牌主要依賴滑鼠射線 | 第一版 Windows Demo 可先以滑鼠為標準；控制器與觸控延後 |

UI 的判斷順序固定為「玩家現在能做什麼 → 選到什麼 → 會影響誰 → 結果是什麼」。例如魔力不足的卡在手牌就應降低亮度，滑過仍能看全文；玩家不需要拖到場上後才收到拒絕訊息。

## 建議製作順序

1. 先挑 12–18 個效果動畫，覆蓋六個效果家族，不整包匯入。
2. 建 `FxProfile`／`FxDirector`，先接「普攻、火焰、冰凍、治療、護盾、回魔、反制」七條代表流程。
3. 為每條流程配一組 SFX，加入 Audio Bus 與音量設定。
4. 補 UI 行動狀態、可出牌提示與結算紀錄，再跑三種解析度／兩種 UI 比例驗收。
5. 做兩副固定試玩牌組與首局教學，讓新玩家不用讀 README。
6. 跑完整單人試玩、Windows 匯出與授權檢查，再決定是否進公開 Demo。
